🏅 UPC 竞赛小档案

  • 赛制：3 人一队，48 小时内从 A/B 两题中选一题，用物理学原理分析给定场景，写成正式英文论文（含摘要、建模、数值/解析求解、讨论、参考文献）。
  • 评审：分四档（官方口径）——Gold Medal 约 2%、Silver 15–20%、Bronze 25–30%、Accomplished Competitor 50–60%；逐年实际比例见 02_官方成绩单/。
  • 风格：题目开放、贴近真实研究情境（航天、生物物理、运动科学、能源、信号处理……），不设标准答案，重"物理建模的完整性与自洽性"而非"算出一个数"。
  • 主办：Kelly S. Cline（Carroll College，美国蒙大拿州海伦娜）。

🌐 部署为网站（GitHub Pages）

本档案库自带一个纯静态站点：根目录 index.html（总览导航 + 全文搜索）+ 09_可视化总览/docs/（235 个 Markdown 文档渲染成的网页，公式用 KaTeX、流程图用 mermaid）。仓库根目录已备好部署辅助文件：

  • .nojekyll —— 关闭 GitHub Pages 的 Jekyll 处理（否则 _工具脚本 等下划线目录会被忽略）
  • index.html —— 站点首页本体（访问 / 直接打开，不再做跳转，分享出去的 URL 干净）
  • 404.html —— 自定义 404 页（GitHub Pages 会对任何缺失路径返回它）
  • search-index.js —— 235 份文档的全文索引（约 312 KB，首次输入搜索时才加载，不拖慢首屏）
  • .gitignore —— 白名单模式：只提交十二个档案目录、赛时工具、知识提炼、AI 技能、站点资源与 README，忽略本目录下的其他个人文件（LaTeX 安装包、视频、课件等约 6.5 GB）

外部依赖已全部本地化：KaTeX / Mermaid 存放在 09_可视化总览/vendor/，由 _工具脚本/_fetch_vendor.py 一次性拉取（默认 unpkg，可用 VENDOR_MIRROR 换源）。站点运行时不请求任何外部资源（唯一例外：数值实验台按需加载 Pyodide 运行时），国内网络下公式与流程图都能正常渲染。

注意：档案内容约 155 MB（论文 PDF 118 MB + 页面图 23 MB + 前端依赖 3.7 MB），远低于 GitHub 单文件 100 MB / 站点 1 GB 的限制，可直接托管；论文原为官网公开物，注明来源即可。

部署三步：① 在 GitHub 新建 Public 仓库 → ② 本目录 git init && git add -A && git commit -m "UPC archive" && git branch -M main && git remote add origin <你的仓库地址> && git push -u origin main → ③ 仓库 Settings → Pages → Source 选 Deploy from a branch + main + / (root) → 保存，1–3 分钟后访问 https://<用户名>.github.io/<仓库名>/。

重建站点

python _工具脚本/_fetch_vendor.py   # 仅首次，或升级 KaTeX/Mermaid 时
python _工具脚本/_build_site.py      # 重新渲染 235 个文档页 + 6 个赛时工具页 + 首页 + 404 + 搜索索引
python _工具脚本/_site_check.py      # 独立体检（断链/大小写/未入库/索引同步；--external 附加外链抽查）

_build_site.py 结束时会做大小写敏感 + git 跟踪感知的链接校验（静态 href/src、DATA 里运行时注入的 URL、赛时工具页的链接都查）。任何一处断链（包括「文件存在但没进 git」这种只在 Linux 服务器上才会暴露的情况）都会让构建以非零码退出并列出行号级别的清单，不会再出现"本地一切正常、线上全 404"。提交时 .git/hooks/pre-commit 还会再跑一次快速体检拦截。

AI 技能与模式卡片管线

.agents/skills/ 下 7 个 ZCode 技能（同仓库协作时自动触发，换机器随仓库走）：upc-modeling（建模教练，按判据→基准→量级表→主模型→验证流程带练）、upc-writing（按金牌句库改写/翻译）、upc-figures（图表教练，配方库+73 篇图型库）、upc-review（评委视角审查+分档预判）、upc-site-check（站点体检解读与修复）、upc-new-edition（新一届赛事入库 SOP）、upc-content-style（库内内容体例规范）。

技能的知识底座是模式卡片管线：_extract_knowledge.py（抽取 73 篇赏析的「获奖密码/可借鉴清单」与精读的「骨架/决策链/可复用模板」）→ 多智能体逐篇提炼为结构化卡片（_知识提炼/卡片/，schema 见 _知识提炼/卡片任务说明.md）→ _aggregate_cards.py 聚合为 4 份知识库（_知识提炼/汇总/）。新一届论文入库后重跑一遍即可让教练知识库同步更新。

讨论区（giscus，可选）

文档页已预留评论区挂载点（零默认请求；repo 字段已预填）。启用剩三步：

  1. 打开 giscus.app/zh-CN，输入仓库 L-zer0Coder/upc-archive——它会引导你：① 仓库 Settings → General → Features 勾选 Discussions；② 安装 giscus App 到该仓库；③ 选一个分类（建议 Announcements，只有维护者能开帖）。
  2. 把生成配置里的 data-repo-id 与 data-category-id 两个值（以及分类名）填进 _工具脚本/_build_site.py 的 GISCUS={...} 四字段。
  3. python _工具脚本/_build_site.py 重建推送。四个字段齐备前评论区不加载，站点零外部请求。

赛事时钟

首页 hero 下方与每个文档页顶栏都有赛事时钟，三态自动切换：赛前倒计时 → 赛中计时（已用/剩余/进度条/当前阶段）→ 赛后归档。赛中会把当前时间落到 48小时作战手册.md 的 T0–T9 阶段上，直接告诉你"现在该干什么、还剩几小时"。

时间点只在 _工具脚本/_build_site.py 顶部改这两行即可，改完重建：

EVENT_START_MS = 1794013200000   # 2026-11-07T09:00:00+08:00（UTC 毫秒）
EVENT_END_MS   = EVENT_START_MS + 48 * 3600 * 1000
PHASES = [...]                   # 小时区间 → 阶段名，与作战手册对齐

用绝对时间戳而非日期字符串，访问者无论在哪个时区看到的都是同一时刻；页面隐藏时计时器自动停跳，回到前台立刻校正。
